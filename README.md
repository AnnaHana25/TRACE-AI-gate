# TRACE-AI-gate: панель людського нагляду за ШІ-агентами

Курсова робота з дисципліни «Надійність та захист інформації в комп'ютерних системах та мережах».
Тема: «Проєктування захищеного інтерфейсу людського нагляду за ШІ-агентами програмування».

Панель показує сесії агента, заблоковані дії та порушені правила, справи для рішення людини,
метрики якості та стан журналу доказів (хеш-ланцюг SHA-256).

## Технології

| Частина | Технологія |
|---|---|
| Бекенд | Python, FastAPI |
| База даних | PostgreSQL (psycopg2) |
| Фронтенд | HTML, CSS, JavaScript (без фреймворків) |
| Безпека | SHA-256, перевірка цілісності, модель загроз |

## Запуск

```bash
pip install -r requirements.txt

# 1. створити базу даних і таблиці
createdb trace_gate
psql -d trace_gate -f sql/schema.sql

# 2. налаштування: скопіювати .env.example у .env і вписати свої значення

# 3. заповнити БД демо-даними й завантажити журнал
python backend/seed.py

# 4. запустити сервер
uvicorn main:app --app-dir backend --port 8000
```

Панель: http://localhost:8000

## Тести

```bash
python -m pytest tests -v
```

Перевіряють алгоритм хеш-ланцюга на підроблених даних (сценарії Т1-Т7) і швидкодію на 10 000 записів.

## Як влаштована безпека

1. **Панель лише показує.** Усі ендпоінти читання (GET) нічого не змінюють.
2. **Рішення людини - окремий канал.** `POST /api/decide` вимагає PIN (з `.env`), після 5 помилок
   блокується на хвилину, приймає лише дії зі статусом «потребує людини», кожне рішення пишеться в журнал.
3. **Перевірка перед показом.** При кожному відкритті екрана перевіряється хеш-ланцюг, копія БД
   звіряється з оригіналом (`data/journal.jsonl`), а вердикти в таблиці дій - з журналом.
4. **Захист від XSS і clickjacking.** Текст виводиться через `textContent`, сервер додає заголовки
   CSP та `X-Frame-Options: DENY`.
5. **SQL-ін'єкції неможливі:** усі запити параметризовані.

## Демонстрація атак

Скрипт `demo_tamper.py` імітує дії шкідливого агента (окремо від панелі). Після кожної команди
оновіть сторінку - угорі з'явиться тривога.

```bash
python backend/demo_tamper.py payload 8           # змінити запис, хеш не чіпати
python backend/demo_tamper.py delete 10           # видалити запис
python backend/demo_tamper.py resync 8            # змінити запис і перерахувати весь ланцюг
python backend/demo_tamper.py verdict act_005 approved   # підмінити вердикт у таблиці
python backend/demo_tamper.py restore             # відновити з оригінального журналу
```

## Структура

```
sql/schema.sql          схема БД
backend/
  main.py               API (FastAPI) і канал рішень
  hashchain.py          алгоритм хеш-ланцюга, перевірка, звірка з оригіналом
  journal.py            читання/запис журналу (файл і БД)
  seed.py               демо-дані і завантаження журналу в PostgreSQL
  demo_data.py          зміст демо-даних
  threats.py            модель загроз
  demo_tamper.py        імітація атак
  db.py, config.py      підключення до БД, налаштування
frontend/               index.html, style.css, app.js
tests/test_hashchain.py тести на підроблених даних
```

## Обмеження прототипу

- Оригінальний журнал лежить на тому ж комп'ютері, що й агент. Для повного захисту від
  перерахунку ланцюга (загроза T-05) останній хеш треба зберігати в окремому сховищі.
- PIN у прототипі перевіряється сервером панелі. У реальній системі рішення має підтверджуватися
  окремим пристроєм (наприклад, апаратним ключем).
- Автентифікації користувачів панелі немає.
